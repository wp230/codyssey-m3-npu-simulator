# Mini NPU Simulator

본 프로젝트는 AI 연산의 핵심인 **MAC(Multiply-Accumulate, 곱셈-누적) 연산**의 원리를 이해하고, 다양한 크기($3 \times 3 \sim 25 \times 25$)의 패턴을 판별하는 Python 기반 Mini NPU 시뮬레이터입니다.

---

## 1. 실행 방법 (How to Run)

### 1) 실행 환경
- **Python 버전**: Python 3.8 이상
- **외부 라이브러리**: 없음 (Python 표준 라이브러리 `json`, `time`만 사용)

### 2) 실행 명령어
프로젝트 루트 디렉토리에서 아래 명령어를 실행합니다.
```bash
python main.py

```

### 3) 모드 선택

실행 후 콘솔 안내에 따라 번호를 입력합니다.

* `1`: **사용자 입력 모드 (3×3)**
* 필터 A, 필터 B, 입력 패턴을 각각 3줄에 걸쳐 공백 구분 숫자로 직접 입력합니다.


* `2`: **data.json 분석 모드**
* 같은 디렉토리에 위치한 `data.json` 파일을 로드하여 크기별 필터 및 패턴을 일괄 검증하고 성능을 분석합니다.



---

## 2. 주요 구현 요약 (Implementation Summary)

### 1) 순수 MAC 연산 (`mac_operation`)

* NumPy 등 외부 벡터화 라이브러리를 배제하고, 순수 2중 반복문을 통해 위치별 곱셈과 누적 덧셈을 수행합니다.
* 연산식:

$$Score = \sum_{r=0}^{N-1} \sum_{c=0}^{N-1} (Pattern[r][c] \times Filter[r][c])$$



### 2) 라벨 표준화 및 정규화 (`normalize_label`)

* `data.json` 내부의 다양한 라벨 표기(`'+'`, `'cross'`, `'Cross'` $\rightarrow$ `'Cross'`, `'x'`, `'X'` $\rightarrow$ `'X'`)를 내부 표준 라벨(`'Cross'`, `'X'`)로 일원화하여 비교 오류를 방지했습니다.

### 3) 부동소수점 오차 방어 및 판정 정책 (`evaluate_scores_mode2`)

* IEEE 754 부동소수점 연산에서 발생하는 미세 오차(Round-off error)를 제어하기 위해 허용오차 $\varepsilon = 10^{-9}$ 기준의 판정 정책을 적용했습니다.
* $|Score_{\text{Cross}} - Score_{\text{X}}| < 10^{-9}$ 인 경우, 모호한 판단을 배제하고 `UNDECIDED`(판정 불가)를 반환합니다.

### 4) 순수 연산 구간 성능 측정 (`measure_mac_performance`)

* 파일 I/O 및 콘솔 출력 오버헤드를 배제하고, 순수 `mac_operation` 호출 구간만을 `time.perf_counter()`로 10회 반복 측정하여 평균 실행 시간(ms)을 산출했습니다.

### 5) 방어적 에러 핸들링

* 행렬 차원 불일치, JSON 스키마 누락, 파싱 오류 발생 시 프로그램이 강제 종료되지 않고 해당 케이스만 `FAIL` 처리 및 원인 로그를 남기도록 격리 설계했습니다.

### 5) 시간 복잡도 $O(N^2)$ 분석 및 NPU 도입 배경

1. **이론적 복잡도 도출**:
* $N \times N$ 크기의 정방 행렬에서 총 원소의 개수는 $N \times N = N^2$개입니다.
* 각 원소마다 1회의 곱셈과 1회의 누적 덧셈이 순차적으로 실행되므로 총 연산 횟수는 $2N^2$번에 수렴하며, 점근적 시간 복잡도는 $O(N^2)$가 됩니다.


2. **데이터 크기 증가에 따른 연산량 급증**:
* $3 \times 3$ (9회) 대비 $5 \times 5$는 약 2.78배(25회), $13 \times 13$은 약 18.78배(169회), $25 \times 25$는 약 69.44배(625회)로 연산 횟수가 기하급수적으로 증가합니다.
* 한 변의 길이($N$)가 약 8.3배($3 \rightarrow 25$) 커질 때, 연산량은 약 70배 가까이 폭증함을 실험 데이터와 이론을 통해 확인할 수 있습니다.


3. **CPU 직렬 처리의 한계와 NPU의 필요성**:
* 본 시뮬레이터와 같은 범용 CPU 구조는 중첩 반복문을 통해 원소를 하나씩 순차(직렬) 처리하므로 $N$이 커질수록 지연 시간이 필연적으로 증가합니다.
* 실제 딥러닝 모델에서는 수백 $\times$ 수백 크기의 텐서 수만 개를 처리해야 하므로 수억~수조 번의 MAC 연산이 요구됩니다.
* 따라서 이러한 대규모 단순 반복 MAC 연산을 수천 개의 연산기(Systolic Array 등)를 통해 한 번에 병렬 처리하는 전용 가속기(NPU)가 AI 시스템에 필수적임을 알 수 있습니다.
